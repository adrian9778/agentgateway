## 0. 结论速览

本目录是 agentgateway 的**源码阅读文档库**，按「先总结、先生产、再逐层拆解」组织成四层。本篇约定：读者按什么顺序读、每篇的章节骨架、源码引用怎么写、哪些词是禁止的。所有篇目共用一套锚点记法与四个事实标记，保证任何结论都能顺着锚点回到当前工作区源码。

### 0.1 阅读顺序（四层是阅读深度的递进）

### 0.2 两条组织铁律

1. **先生产后开发**：每篇先写「系统现在实际能做什么、怎么用、得到什么结果」，再补「代码在哪里、怎么实现」。不得从文件名、类名、包名、框架名开场。
2. **每层先小结后细节**：每一层先给本层小结，再列具体条目。

## 1. 源码锚点记法（`符号 + 偏移`，不用裸行号）

行号会随重构漂移，所以正文引用一律用「符号 + 偏移」。`+0` = 目标符号的**签名行**（偏移 = 目标行 − 签名行）。

| 场景 | 写法 | 示例 |
|---|---|---|
| Rust 自由函数 / 方法签名 | `文件 · 符号 +0` | `crates/agentgateway-app/src/lib.rs · pub fn run +141` |
| 函数内某行 | `函数 +偏移` | `run +146`（= 关透明大页那行） |
| 连续片段 | `Foo+0~+20` | `run +148~+158`（选分配器） |
| Rust 方法在 `impl` 块 | 必须写明所属 impl | `store/binds.rs · impl Store · bind_listeners +655` |
| Rust trait 方法 | `impl Trait for Type · 方法 +0` | `impl Default for FormatterConfig · default +0` |
| Go 方法 | `文件 · Receiver.Method +偏移` | `setup/setup.go · (s *setup) Start +183` |
| 类型 / 常量 / 模块 | `Struct：X` / `Const：Y` / `Module：rpc` | `Struct：ListenerTarget` |
| 调用关系 | 标双方 | `调用方 run+168 ↓ 被调用方 commands::run::execute` |
| 第三方依赖 | 注明版本 | `依赖：github.com/spf13/cobra` |

> 文末「源码索引」可给 `文件:函数:绝对行号` 方便跳转复核，但正文锚点仍用符号+偏移。

## 2. 四个事实标记（全库统一，不自造）

| 标记 | 何时用 |
|---|---|
| `[源码未确认]` | 仓库里没找到证据，但也不能断定没有 |
| `[源码未找到]` | 已全量检索，确实不存在 |
| `[推断]` | 有证据支撑的解释，但不是源码原文写的 |
| `[待运行验证]` | 需要外部环境 / 运行期才能确认（生产端口、副本数、实际开关值等） |

冲突口径：README、注释、旧文档与实现不一致时，**以当前工作区实现为准**，并把差异和证据写出来。生产实测（端口、副本数、线上时序）只有实际只读核验后才能写，否则标 `[待运行验证]`。

## 3. 禁止措辞

正文里不允许出现：`TODO` / `TBD` / `FIXME` / 「待补充」/「同上」/「略」/ 省略号顶替核心逻辑 /「相关配置」「按需处理」「诸如此类」这类遮掉具体对象与条件的空话。坐实不了的，写 `[源码未确认]` 并进未决清单，宁可留明确缺口，也不写看似完整实则空洞的段落。

## 4. 图与表的下限

- 实质性篇目至少 **2 张图**：一张生产流程图（节点 = 真实参与者/入口/可见结果）、一张开发实现图（节点 = 真实文件/模块/函数/存储）。
- 至少 **3 张表**：结论速览表、生产条件与结果表、开发源码映射表。
- 跨对象先后用 `sequenceDiagram`，条件分支用 `flowchart`，状态用 `stateDiagram-v2`，多表关系补 `erDiagram`。
- 图下必须用列表交代前提、分支、终点，不能只放图不解释。

- 一篇一落盘，完成即写盘；中断后从 `.progress/` + 已写盘产物续写，不重扫。
